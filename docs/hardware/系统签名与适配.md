# 系统签名与 ZE69 适配

> DSJ-ZECN6A1 的灯控、红外、IR_CUT 通过 **sysfs** 暴露（见 [ZE69-驱动控制接口.txt](ZE69-驱动控制接口.txt)）。  
> 普通 Debug 签名 App **无法写入** 这些节点；需 **platform 系统签名** 或与 ROM 一致的 **release 签名**。

---

## 1. 厂商提供的适配材料

桌面目录 `适配文档`（勿提交 git）通常包含：

| 文件 | 用途 |
|------|------|
| `ZE69-驱动控制接口.txt` | sysfs 路径说明（已同步到本目录） |
| `platform.x509.pem` + `platform.pk8` | **platform** 系统签名（写 sysfs、priv-app） |
| `releasekey.x509.pem` + `releasekey.pk8` | **release** 签名（与 ROM 一致） |
| `k69v1_64_ZE69_ZY_3G.../` 刷机包 | MT6768 scatter + `super.img` |

证书与 **`.pk8` 私钥** 仅放本地适配目录，**不得入库**。完整步骤见 [ZE69刷机与预装.md](ZE69刷机与预装.md)。

---

## 2. 为何需要系统签名

| 能力 | 无系统签名 | 有系统签名 |
|------|-----------|-----------|
| 写 ZE69 sysfs 灯控 | ❌ 静默失败 | ✅ |
| 开机自启、常驻后台 | 受限 | ✅ 可声明系统 App |
| 低功耗唤醒监听 | 受限 | ✅ |

代码入口：`android-app/.../platform/Ze69Hardware.kt`、`NightVisionController.kt`。

真机自检：设置 → 设备信息应显示「已检测到 ZE69 驱动节点」或「型号匹配（sysfs 需系统签名写入）」。

---

## 3. 签名流程（概要）

1. 使用适配文档内 `platform.pk8` + `platform.x509.pem`（见 [ZE69刷机与预装.md](ZE69刷机与预装.md) P0-2）。
2. 在 **Android 源码树** 或 **signapk** 工具链中，用 platform/release 密钥对 APK 重签。
3. 将签后 APK **预装或 adb install -r** 到执法仪；必要时将包名加入 ROM 白名单。
4. 验证：开始录像 → **红绿灯绿灯** 亮；弱光环境 → **红外 + IR_CUT** 自动切换。

具体命令因厂商 ROM 而异，以致业/ZE69 交付的《适配文档》为准。

---

## 4. 开发阶段策略

| 阶段 | 做法 |
|------|------|
| **联调 AI / 录像** | Debug 包即可；灯控失败不影响 Camera2 主路径 |
| **演示灯控 / 夜视** | 使用厂商签名的 release/platform 包 |
| **量产** | 系统级主控 App + OTA（见 [产品设计方案.md](../product/产品设计方案.md) P4） |
