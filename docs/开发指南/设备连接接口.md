# 设备连接接口文档

> **实现真相**：`backend/app/device_bind/`、`backend/app/command_call/router.py`（MQTT 配置）、执法仪 `ApiClient` / `MqttClient`。  
> **领域术语**：根目录 [`CONTEXT.md`](../../CONTEXT.md)。  
> **默认基址**：`http://<主机>:8000`（以 `ApiConfig` / 环境变量为准）。  
> **四端总览**（设备 / 手机 / Web / 后端关系）：[`四端连接总览.md`](四端连接总览.md)。

本文描述执法仪从**入库**到**扫码占用**再到 **MQTT 信令上线**的完整连接契约，供执法仪、手机 App、管理后台对接。

---

## 1. 连接全景

```
管理后台                执法仪 App                    手机 App                 云端
   │                      │                            │                      │
   │── PATCH company ─────┼────────────────────────────┼────► 设备入库        │
   │                      │                            │                      │
   │                      │── POST bind/token ─────────┼────► 短期扫码凭证    │
   │                      │◄── token + qr_url ─────────┼──────────────────────│
   │                      │ 展示 QR                    │                      │
   │                      │                            │── mobile/login ─────►│
   │                      │                            │── bind/confirm ─────►│ 建立占用
   │                      │── GET bind/status 轮询 ────┼─────────────────────►│
   │                      │◄── bound + session_token ──┼──────────────────────│
   │                      │── GET mqtt/client-config ──┼────► EMQX/IoT 参数   │
   │                      │══ MQTT CONNECT + SUB ═════════════════════════════╡ Broker
   │                      │   （指挥连线 / 监看 start|end）                    │
```

| 阶段 | 含义 | 权威端点 |
|------|------|----------|
| **设备入库** | 管理后台把 `DSJ-` 登记入 `recorders` 并绑定 `company` | `PATCH /v1/recorders/{device_id}/company` |
| **扫码绑定** | 在岗人员临时占用设备，签发执法仪 `session_token` | `/auth/device/bind/*` |
| **信令上线** | 设备拉取 MQTT 参数并订阅指挥 topic | `GET /v1/mqtt/client-config` + Broker |

媒体面（监看 / 指挥连线）走 **腾讯云 TRTC**，不经本仓库中转音视频；信令走 MQTT（主）+ HTTP poll（兜底）。详见 [`通信协议规范.md`](../架构与数据/协议/通信协议规范.md)、[`ADR-0002`](../决策记录/0002-trtc-for-command-calls.md)。

## 2. 前置条件

1. 设备已出现在公司设备池：`device_id`（如 `DSJ-…`）已入库且 `company` 非空。  
2. 人员档案在岗、与设备同公司；一人同时最多一机，一机同时最多一人。  
3. 故障设备（`is_faulty`）不可绑定。  
4. 手机确认绑定前须先完成 `POST /auth/mobile/login`（人脸），拿到 Bearer。

未入库设备申请 token 时返回：`设备尚未入库绑定公司，请联系管理员`。

## 3. HTTP 接口一览

| 方法 | 路径 | 调用方 | 鉴权 | 作用 |
|------|------|--------|------|------|
| `PATCH` | `/v1/recorders/{device_id}/company` | 管理后台 | 无* | 入库绑定公司 |
| `POST` | `/auth/device/bind/token` | 执法仪 | 无 | 申请短期扫码 token |
| `GET` | `/auth/device/bind/status` | 执法仪 | 无 | 轮询绑定状态 |
| `POST` | `/auth/device/bind/confirm` | 手机 App | Bearer | 扫码确认占用 |
| `POST` | `/auth/device/bind/release` | 执法仪 | 无 | 主动解绑 |
| `POST` | `/auth/device/bind/shutdown` | 执法仪 | 无 | 关机/重启结束占用 |
| `POST` | `/auth/mobile/login` | 手机 App | 无 | 人脸登录，签发 Bearer |
| `GET` | `/v1/mqtt/client-config` | 执法仪 | 无* | 拉取 MQTT 连接参数 |
| `GET` | `/v1/recorders/{device_id}` | 各端 | 无 | 查询设备档案摘要 |

\*生产环境应对管理与 MQTT 配置接口加鉴权；当前便于联调。

扫码绑定成功后，后端会尝试 `ensure_occupancy_room`（占用侧持房）；解绑/关机时 `release_occupancy_room`。

## 5. 扫码占用（设备连接会话）

短期 token 默认 TTL：`DEVICE_BIND_TOKEN_TTL` 环境变量，默认 **180 秒**。  
二维码内容：`{PUBLIC_API_BASE}/bind?device={device_id}&token={token}`（未配置 `PUBLIC_API_BASE` 时返回相对路径）。

### 5.1 `POST /auth/device/bind/token`

**请求**

```json
{ "device_id": "DSJ-abc123" }
```

**成功 200**

```json
{
  "ok": true,
  "device_id": "DSJ-abc123",
  "token": "<urlsafe>",
  "expires_at": "2026-07-30T08:03:00+00:00",
  "qr_url": "https://api.example.com/bind?device=DSJ-abc123&token=...",
  "ttl_seconds": 180
}
```

**失败 400**：未入库、`device_id` 无效等（`detail` / `message`）。

同一设备新申请会把旧 `pending` token 标为 `expired`。

### 5.2 `GET /auth/device/bind/status`

| Query | 说明 |
|-------|------|
| `device_id` | 设备编号 |
| `token` | 当前二维码 token |

| `status` | 含义 | 执法仪行为 |
|----------|------|------------|
| `pending` | 等待手机扫码 | 继续轮询；可按 TTL 刷新 QR |
| `bound` | 绑定成功 | 保存 `session_token` 与 `officer`，进入已占用 |
| `expired` | 二维码过期 | 重新申请 token |
| `rejected` | 凭证无效 / 被拒 / 占用已结束 | 提示后刷新或回到未绑定 |

**`bound` 响应示例**

```json
{
  "ok": true,
  "status": "bound",
  "device_id": "DSJ-abc123",
  "token": "...",
  "session_token": "<执法仪后续 API Bearer>",
  "officer": {
    "employee_id": "E001",
    "name": "张三",
    "gender": "男",
    "phone": "138****0000",
    "department": "巡查一组",
    "company": "某某建设",
    "position": "组员",
    "id_card": "",
    "status": "active",
    "status_label": "在岗"
  }
}
```

### 5.3 `POST /auth/device/bind/confirm`

**Header**：`Authorization: Bearer <mobile_token>`

**请求**

```json
{
  "device_id": "DSJ-abc123",
  "token": "<扫码得到的 token>"
}
```

**校验顺序（后端）**：手机登录有效 → 人员在岗 → 设备未故障 → 同公司 → token 仍为 pending 且未过期 → 设备无人占用（或本人）→ 人员无其他机占用。

**成功 200**：`ok`、`message`、`device_id`、`session_token`、`officer`。  
**失败 403**：占用冲突、非本公司、过期等。

### 5.4 结束占用

| 路径 | `end_reason` | 典型触发 |
|------|--------------|----------|
| `POST /auth/device/bind/release` | `unbind` | 设置内「解绑」 |
| `POST /auth/device/bind/shutdown` | `shutdown` | 整机断电/重启钩子 |

**请求**：`{ "device_id": "DSJ-abc123" }`

**响应**：`ok`、`message`、`released`（`true` 表示结束了占用）、`device_id`。

结束占用会写使用历史，并释放占用侧指挥房。

## 7. MQTT 信令连接

### 7.1 `GET /v1/mqtt/client-config?device_id=`

执法仪在占用建立后（或启动时）拉取 Broker 参数并写入本机 `MqttConfig`。

**响应字段**

| 字段 | 说明 |
|------|------|
| `enabled` | Broker/账号/密码均配置时为 `true` |
| `provider` | 现行联调默认 `emqx`；亦支持本机配置 `aliyun_iot` |
| `broker_uri` | 来自 `MQTT_BROKER_URI` |
| `username` / `password` | 来自 `MQTT_DEVICE_USERNAME` / `MQTT_DEVICE_PASSWORD` |
| `client_id` | `MQTT_DEVICE_CLIENT_ID` 或回退为 `device_id` |
| `topic_prefix` | 默认 `aifieldcam/command_call`（`MQTT_TOPIC_PREFIX`） |
| `subscribe_topics` | `[{prefix}/{deviceId}/start`, `{prefix}/{deviceId}/end]` |

**响应示例**

```json
{
  "enabled": true,
  "provider": "emqx",
  "broker_uri": "tcp://mqtt.example.com:1883",
  "username": "device",
  "password": "***",
  "client_id": "DSJ-abc123",
  "topic_prefix": "aifieldcam/command_call",
  "subscribe_topics": [
    "aifieldcam/command_call/DSJ-abc123/start",
    "aifieldcam/command_call/DSJ-abc123/end"
  ]
}
```

### 7.2 客户端连接约定

| 项 | EMQX（现行联调） | 阿里云 IoT（可选） |
|----|------------------|-------------------|
| 认证 | 用户名 + 密码 | 三元组 HMAC-SHA256 |
| 订阅 | `{prefix}/{deviceId}/start\|end` | `/sys/{pk}/{dn}/thing/service/command_call/start\|end` 等 |
| KeepAlive | 60s（执法仪 Paho） | 同左 |
| 开关 | `MqttConfig.enabled`；`enabled=false` 时不建连 | 同左 |

实现：`android-app/.../MqttConfig.kt`、`MqttClient.kt`、`MqttTopicRouter.kt`。

### 7.3 与 HTTP 兜底的关系

- 指挥/监看 **start|end**：MQTT 下发为主；设备消费后应 `POST /v1/command-call/{call_id}/device-ack`（或占用房 join-ack）标记送达。  
- 未配置 MQTT 或断线时，设备仍可 `GET /v1/command-call/device/{device_id}/poll` 拉取命令。  
- 两条路径须去重处理。设计见 [`mqtt-ack-yuv 规格`](../superpowers/specs/2026-07-30-mqtt-ack-yuv-cocapture-design.md)。

## 8. 状态机（设备占用）

```
未入库 ──[PATCH company]──► 可扫码（未占用）
可扫码 ──[confirm 成功]──► 已占用
已占用 ──[release|shutdown]──► 可扫码（写 usage history）
已占用 ──[他人 confirm]──► 拒绝（token → rejected）
已占用(人A) ──[人A 在 B 机 confirm 且未 release A]──► 拒绝
```

息屏 / App 后台**不**结束占用；整机重启应走 `shutdown`。

## 9. 错误与约定摘要

| 场景 | HTTP | 典型文案 |
|------|------|----------|
| 未入库 | 400 | 设备尚未入库绑定公司 |
| 二维码过期 | 200/`expired` 或 confirm 403 | 二维码已过期 |
| 设备被占用 | 403 | 该执法仪已被其他人员占用 |
| 人已占用他机 | 403 | 您已在设备 … 占用中 |
| 非本公司 | 403 | 非本公司设备，无法绑定 |
| 故障机 | 403 | 本执法仪已标记故障 |
| 手机未登录 | 403 | 请先登录手机 App |

通用约定：

- JSON；成功体常含 `ok: true`。  
- 执法仪绑定轮询与 token 申请当前**无** Bearer；`session_token` 用于后续 AI 等需鉴权接口。  
- `device_id` 最小长度 4（Pydantic）；与本机序列号/`DeviceIdentity` 一致。
